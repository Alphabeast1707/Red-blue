Why We Built This
Most security tools only recognise attacks they have already seen before.
Change a few characters in an attack, and it walks straight past them.
Companies hire experts to test their defences, but only once or twice a year  the rest of the year is a blind spot.
Real attack data is expensive to collect, and whatever exists goes stale quickly.
Our idea: let an attacker AI and a defender AI fight each other non-stop, so the defender keeps meeting attacks nobody has seen before.

Objectives
Sandboxed Cyber Range: Built an isolated, controlled environment for safely simulating adversarial security testing without impacting production systems.
Autonomous Red-Team Agent: Developed an LLM-driven attacker that generates exploit payloads, applies evasion techniques, validates outcomes via HTTP responses, and adapts to defensive countermeasures.
Adaptive Blue-Team WAF: Implemented an LLM-powered defense engine that inspects requests inline, detects malicious payloads, and dynamically generates mitigation rules.
Orchestration Engine: Built a round-based controller to coordinate attack–defense iterations, manage state transitions, and capture reproducible execution traces.
Automated Ground-Truth Collection: Created a structured corpus pipeline recording payloads, attack techniques, verified breaches, and detection verdicts for continuous model improvement.
ML-Based Detection Benchmarking: Trained a character n-gram + logistic regression classifier, achieving 94% recall on unseen evasion techniques vs. 33% for static signatures in proof-of-concept testing.
Reproducible Evaluation Dashboard: Developed an interactive dashboard for visualizing attack progression, defense adaptation, vulnerability remediation, and detection metrics, with offline session replay.

Red Agent: How It Chooses, Evolves and Confirms Attacks
LLM Attack Planner — Each round the attacker (Azure gpt-6-luna) reads how the defender just responded and chooses which vulnerability family to press and which evasion technique to apply. It plans strategy only — it never writes raw exploit code.
Five Deterministic Evasion Transforms — A tool turns each plan into a real payload by transforming the standard DVWA attack strings: case-flipping, inline-comment injection, URL encoding, double encoding, and vector pivoting. Safe and reproducible; no external data feed.
Grounded Verification — After every un-blocked probe the attacker reads the target's actual HTTP response and confirms what it achieved — leaked data, command output, file contents. A finding backed by evidence, not a guess.
Feedback-Driven Adaptation — The next wave is conditioned on the last: families that breached are pressed harder; families that were blocked trigger a technique switch or a pivot to whatever is still open. The attack stream genuinely escalates against this defender.
No Raw Exploit Synthesis (by design) — A well-aligned model refuses to author novel exploit code, and we do not bypass that. The attacker's intelligence is in adaptation and verification of known attack classes — not in inventing new zero-days.
Graceful Fallback — If the model is unreachable, the attacker falls back to scripted mutation operators for that round, so a live run never stalls.

Conclusion & Future Scope
We have a complete, working arena where an LLM attacker and an LLM defender genuinely fight against a real vulnerable site — not a mock-up.
The attacker discovers and confirms vulnerabilities from real responses; the defender blocks inline and learns a new patch for every breach it sees.
Every exchange is auto-labeled into a corpus, and a detector trained on it catches 94% of unseen evasions versus 33% for static rules — the loop is closed end to end.
The production detector is Laya, an open 421M decision model; fine-tuning it on the full corpus and automating the retrain with RL are the next steps.
Longer term: more vulnerability classes and real apps, one shared model calibrated per environment, and releasing the labeled dataset and benchmark.
